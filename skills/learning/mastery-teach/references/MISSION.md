# Mission protocol

The mission is a compact contract for what "success" means in this workspace.

Create `MISSION.md` with:

```md
# Mission: {domain}

## Why
{Concrete real-world reason.}

## Target scope
{What part of the domain and what intended depth.}

## Success looks like
- {Observable capability}
- {Observable capability}
- ...

## Constraints
- {time, budget, tooling, access, schedule, learning preferences}

## Out of scope
- {adjacent area deliberately excluded}

## Assessment preference
{Desired rigor, credentials/exams if relevant, tolerance for external assignments.}
```

## Rules

A vague wish such as "understand databases" is insufficient for curriculum boundaries. Convert it into observable capabilities and a target depth.

Ask only questions that materially change the map, resources, assessment strategy, or teaching cadence.

Do not treat the mission as frozen. If it changes, confirm the change, update `MISSION.md`, record why, and determine whether the map needs a partial audit.
