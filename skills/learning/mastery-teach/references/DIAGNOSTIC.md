# Initial diagnostic protocol

The diagnostic estimates a starting point without forcing the learner to sit an exam over the whole map.

## Principles

- Claimed prior knowledge is useful routing information, not verified mastery.
- Sample gateway competencies that unlock large branches.
- Start near the learner's claimed level and adapt upward/downward.
- Prefer production: explain, solve, predict, design.
- Stop testing a branch once you can place the learner well enough to choose useful next work.
- Never award mastery solely from the initial diagnostic unless unusually strong independent prior evidence is available.

## Procedure

1. Read `MISSION.md` and the map.
2. Ask for a concise self-placement if not already known.
3. Select 3–7 high-leverage gateway nodes across the mission's core branches.
4. For each, pose one task at an estimated functional/proficient boundary.
5. If performance is strong, test a dependent node or a more novel version.
6. If weak, test an easier prerequisite.
7. Record evidence and stop when the next-learning frontier is reasonably clear.
8. Create `PROGRESS.yaml`.
9. Mark untested nodes as level 0; do not infer mastery through adjacency.
10. Render the learner map.

Use external diagnostic material if a reputable placement test exists and fits the mission.
